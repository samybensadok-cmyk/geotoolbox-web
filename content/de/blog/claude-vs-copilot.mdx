Claude oder Copilot? Fürs Programmieren ist GitHub Copilot für die meisten Entwickler die bessere Standardwahl: Es sitzt im Editor, kostet im Pro-Tarif 10 $ im Monat und lässt dich das Modell dahinter wählen, auch Claude. Claude Code, Anthropics Terminal-Agent (20 $ im Monat mit Claude Pro), ist die bessere Wahl, wenn die Aufgabe selbstständige Arbeit über viele Dateien ist, etwa ein großes Refactoring oder eine Migration. Meinst du Microsoft 365 Copilot, den Assistenten in Word, Excel und Teams, zeigt dir der Abschnitt „Welcher ‚Copilot‘ ist gemeint?“, wo du weiterliest.

Viele Vergleiche werfen die Produkte durcheinander oder zitieren Benchmark-Zahlen, die es nie gab. Deshalb haben wir jede Zahl im November 2026 auf den Seiten der Anbieter geprüft. Hier liest du, wie sich die beiden unterscheiden, was sie in Deutschland wirklich kosten, was für Datenschutz und DSGVO gilt und wie du dich ohne Schönrechnerei entscheidest.

## Das Wichtigste in Kürze

- **Für die meisten Entwickler ist GitHub Copilot die bessere Standardwahl, Claude Code gewinnt bei eigenständiger Arbeit über viele Dateien (Stand 5. November 2026):** Copilot sitzt im Editor und liegt bei Tempo, Editor-Vielfalt und GitHub-Anbindung vorn. Claude Code ist ein Terminal-Agent für große Refactorings und Migrationen. Viele setzen beide ein.
- **„Copilot“ meint drei verschiedene Dinge:** GitHub Copilot (Coding), Microsoft 365 Copilot (Büro, ab 18,20 € pro Nutzer und Monat zzgl. MwSt.) und Claude als Modell in GitHub Copilot (nicht dasselbe wie Claude Code).
- **Beim Preis kommt es auf Abrechnungsmodell und Buchungsweg an:** Copilot Pro kostet 10 $ im Monat und enthält KI-Credits im Wert von 15 $, Claude Pro kostet 20 $ (17 $ bei Jahreszahlung). In Euro zeigt der EU-Web-Checkout für Claude Pro 18 € netto, der deutsche App Store 22,00 €. GitHub nennt auch auf der deutschen Seite nur Dollar.
- **Beim Kontextfenster liegt Claude Code vorn:** 1 Mio. Token auf jedem bezahlten Tarif. Copilot bietet das nur für unterstützte Modelle in VS Code und der CLI, und das große Fenster verbraucht mehr Credits.
- **Beim Datenschutz kommt es auf den Kontotyp an:** Seit dem 24. April 2026 darf GitHub bei Copilot Free, Pro, Pro+ und Max mit deinem Code trainieren, solange du nicht widersprichst. Bei Claude Free, Pro, Max und Ultra gilt dasselbe Opt-out-Prinzip. Für die DSGVO brauchst du einen Geschäftszugang mit Auftragsverarbeitungsvertrag.

## Claude vs. Copilot im Überblick (Stand November 2026)

Beide Werkzeuge helfen beim Programmieren, aber sie sind grundverschieden gebaut. **GitHub Copilot ist ein Assistent, der im Editor sitzt:** Er schlägt Code beim Tippen vor, beantwortet Fragen im Editor-Chat, hat einen Agent-Modus und ist direkt in GitHub und Pull Requests eingebunden. Welches Modell dahinter läuft, wählst du selbst. **Claude Code ist ein Agent, der im Terminal arbeitet:** Du gibst ein Ziel vor, er plant, ändert mehrere Dateien, führt Befehle aus und prüft seine eigene Arbeit. Dabei nutzt er ausschließlich Modelle von Anthropic.

Die sinnvolle Antwort auf „Was ist besser?“ ist deshalb eine Gegenfrage: „Wofür?“ Copilot ist im Vorteil bei Tempo im Editor, bei der Zahl unterstützter Editoren und überall dort, wo GitHub im Spiel ist. Claude Code ist im Vorteil bei selbstständiger Arbeit über viele Dateien, etwa bei großen Refactorings und Migrationen. Viele Entwickler setzen beide ein, und in einem bezahlten Copilot-Tarif lassen sich Aufgaben sogar an Claude-Agenten übergeben.

**GitHub Copilot** ist der Coding-Assistent. Er sitzt im Editor und auf GitHub, schreibt und prüft Code und ist gemeint, wenn Entwickler ihn mit Claude Code vergleichen. Um dieses Produkt geht es in diesem Artikel.

**Microsoft 365 Copilot** ist der Büro-Assistent: die kostenpflichtige Erweiterung, die in Word, Excel, Teams und Outlook deine E-Mails, Meetings und Dateien liest. Er konkurriert mit Claude im Arbeitsalltag, nicht beim Programmieren. Laut deutscher Microsoft-Seite kostet er ab 18,20 € pro Nutzer und Monat (Copilot Business) und 26,00 € in der Enterprise-Variante, jeweils im Jahresabo und zzgl. MwSt. Wenn du diesen Vergleich suchst, lies zuerst [unseren Überblick zu Microsoft Copilot](https://geotoolbox.ai/blog/what-is-copilot) und danach [Microsoft Copilot vs. ChatGPT](https://geotoolbox.ai/blog/microsoft-copilot-vs-chatgpt). Beim Datenschutz gibt es dort einen Stolperstein: Laut Microsoft Learn sind Claude-Modelle in Microsoft 365 Copilot von der EU Data Boundary ausgenommen. Für Tenants in der EU, im EFTA-Raum und im Vereinigten Königreich sind sie standardmäßig deaktiviert, bis ein Administrator sie freischaltet.

**Claude in Copilot** ist der dritte Fall. Er stiftet Verwirrung, ist aber kein Missverständnis: GitHub Copilot lässt dich Claude-Modelle als Motor für seine Vorschläge wählen. Claude und Copilot sind also nicht immer Konkurrenten. Weil das eine der häufigsten Fragen zum Thema ist, geht der nächste Abschnitt darauf ein.

Im Rest dieses Artikels steht „Copilot“ für GitHub Copilot und „Claude“ für Anthropics Claude, meist in Form von Claude Code.

## Nutzt GitHub Copilot Claude?

Ja, und das überrascht viele, weil ältere Vergleiche noch das Gegenteil behaupten. Eine Aussage wie „Copilot nutzt nur OpenAI-Modelle“ ist veraltet. Auch die Frage, ob GitHub Copilot auf ChatGPT aufbaut, lässt sich damit beantworten: Nein, Copilot arbeitet mit Modellen mehrerer Anbieter.

In VS Code oder auf GitHub öffnest du einen Modellwähler und bestimmst, welches Modell hinter Chat und Agent arbeitet. Claude steht dort zur Wahl. Stand 5. November 2026 nennt [GitHubs Liste der unterstützten Modelle](https://docs.github.com/en/copilot/reference/ai-models/supported-models) die Claude-Modelle Fable 5.1, Fable 5, Opus 5.5, Opus 5, Opus 4.8, Sonnet 5.5, Sonnet 5, Haiku 5.5 und Haiku 4.5, dazu GPT-, Gemini-, Grok-, Kimi- und MAI-Modelle. Sonnet 4.6 hat GitHub am 1. September 2026 abgeschaltet; nur Einzelabos von Pro und Pro+ mit Jahreszahlung behalten es. Welche Modelle du bekommst, hängt von Tarif und Oberfläche ab: Bei monatlicher Zahlung gibt es Opus- und Fable-Modelle erst ab Pro+. Opus 5.5 hat GitHub am Tag der Veröffentlichung, dem 22. September 2026, für Pro+, Max, Business und Enterprise aufgenommen. Außerdem hat GitHub angekündigt, Opus 4.8 und Opus 5 am 16. November 2026 aus Copilot zu nehmen, mit Opus 5.5 als empfohlenem Ersatz; Einzelabos mit Jahreszahlung behalten Opus 4.8.

Copilot kann Claude noch auf einem zweiten Weg nutzen. Laut GitHub-Dokumentation (Stand 5. November 2026) lassen sich in allen bezahlten Copilot-Tarifen Aufgaben an Drittagenten wie Anthropics Claude-Agenten und OpenAI Codex übergeben; die Vergleichstabelle auf GitHubs Preisseite nennt Pro dabei noch nicht. Die Funktion ist eine Public Preview und verbraucht KI-Credits und GitHub-Actions-Minuten. Claude taucht in Copilot damit an einer weiteren Stelle auf, ein Weg zum eigenständigen Claude Code ohne Anthropic-Abo ist das aber nicht.

Zwei Dinge gilt es auseinanderzuhalten. Erstens ist das Claude-Modell in Copilot nicht dasselbe wie Claude Code. Du bekommst die Qualität des Claude-Modells innerhalb von Copilot, im Editor und im Agent-Modus, aber nicht die Arbeitsweise von Claude Code im Terminal mit eigener Dateiverwaltung und Konfiguration. Das Modell ist der Motor, das Werkzeug drumherum das Fahrzeug. Zweitens bringt dir ein Claude-Abo in Copilot nichts: Copilot rechnet seine Nutzung selbst ab, egal welches Modell du wählst; ein Abo bei Anthropic und eines bei GitHub sind zwei getrennte Verträge. Was beide kosten, steht weiter unten.

## Claude Code vs. GitHub Copilot: Terminal-Agent oder Editor-Assistent

Bei Claude Code vs. GitHub Copilot geht es darum, wer steuert. Copilot lässt dich am Steuer und erledigt im Editor jeweils ein kleines Stück; Claude Code nimmt ein Ziel entgegen und erledigt pro Schritt viel, während du prüfst. Diesen Unterschied merkst du schon in der ersten Stunde mit den beiden Werkzeugen, und er prägt fast alle anderen Abwägungen.

GitHub Copilot holt dich dort ab, wo du ohnehin Code schreibst. Es schlägt die nächsten Zeilen vor, während du tippst, beantwortet Fragen im Editor-Chat und übernimmt im Agent-Modus eine Aufgabe, ändert dafür mehrere Dateien und lässt dich im Editor zusehen. Im Mittelpunkt stehen dein Editor und das GitHub-Repository, darum ist der Einstieg reibungsarm: Du musst nichts Neues lernen, und einen Vorschlag übernimmst du mit einem Tastendruck. Bei der Eigenständigkeit hat der Agent-Modus einen großen Teil des Rückstands aufgeholt, aber nicht ganz; das Konzept geht weiterhin davon aus, dass du aus dem Editor heraus steuerst. Außerdem hat Copilot mit der CLI inzwischen einen eigenen Terminal-Agenten, der lokale Befehle ausführt, auf Wunsch in einer lokalen Sandbox. Damit geht es nicht mehr allein um „Editor gegen Terminal“, sondern darum, wie viel Eigenständigkeit du dem Werkzeug überlässt.

[Claude Code](https://geotoolbox.ai/blog/what-is-claude-code) setzt am anderen Ende an. Es arbeitet als Agent im Terminal: Du beschreibst ein Ziel, es liest die Codebasis, schlägt einen Plan vor, ändert die nötigen Dateien, startet Tests oder einen Build, liest die Ausgabe und korrigiert sich selbst. Du beaufsichtigst einen selbstständigen Prozess, statt Vorschläge einzeln anzunehmen. Darum glänzt es bei Aufgaben, die viele Dateien auf einmal betreffen, und darum ist der Einstieg anspruchsvoller als das bloße Annehmen von Vorschlägen.

Beide Werkzeuge lassen sich konfigurieren, und hier überschneiden sie sich. Claude Code liest eine `CLAUDE.md` im Repository mit Projektkontext, Konventionen und Befehlen und unterstützt Hooks, die eigene Skripte an festen Stellen im Ablauf ausführen. Copilot liest benutzerdefinierte Repository-Anweisungen; Copilots Cloud-Agent und die Copilot CLI lesen zusätzlich eine `CLAUDE.md`, der Chat in VS Code die `AGENTS.md`. Eine gemeinsame Kontextdatei kann also beide bedienen. Außerdem binden beide über das Model Context Protocol (MCP) externe Werkzeuge und Daten an. In Reddit-Threads lautet eine verbreitete Klage über Copilot, es verliere bei einer großen Änderung den Faden; über Claude Code heißt es, seine Selbstständigkeit brauche Leitplanken. Das ist dieselbe Beobachtung von zwei Seiten: Das eine lässt dir die Kontrolle und erledigt dafür pro Schritt weniger, das andere erledigt pro Schritt mehr, dafür gibst du Kontrolle ab.

## Editor-Reichweite, Plattformen und Kontextfenster

Bei der Breite an Editoren und Plattformen liegt Copilot vorn, und zwar deutlich. Es läuft in VS Code, Visual Studio, JetBrains-IDEs, Eclipse, Xcode, Neovim, Zed und auf GitHub.com, dazu kommen eine CLI und die Copilot-App. Arbeitet dein Team in einem gängigen Editor, genügt für Copilot ein Plug-in. Claude Code ist auf das Terminal ausgerichtet und bietet dazu Erweiterungen für VS Code und JetBrains, eine Desktop-App und eine Web-Version. Die Editor-Reichweite ist damit schmaler, und das ist so gewollt.

Beim Kontextfenster widersprechen sich die Vergleichsseiten: Die einen nennen 1 Mio. Token, die anderen 200.000. Auch deutsche Beiträge vom April 2026, etwa bei Chudovo und Bluebatch, nennen für Claude noch 200.000 Token. Für die aktuellen Claude-Modelle ist das überholt. Hier die geprüfte Fassung.

In Claude Code nutzen Opus 4.7 und neuer, Sonnet 5 und neuer, Haiku 5.5 und die Fable-Modelle standardmäßig das volle Kontextfenster von **1 Mio. Token**, auf jedem bezahlten Tarif einschließlich Pro. Das große Fenster kostet nichts extra; Fable selbst läuft im Pro-Tarif allerdings nur über Nutzungs-Credits (Anthropic-Dokumentation zur Modellkonfiguration, Stand 5. November 2026). Über die API gibt es 1 Mio. Token zum normalen Preis; nur Haiku 5.5 kostet oberhalb von 100.000 Token mehr pro Token. In der Claude-App bekommen Fable 5.1, Opus 5.5, Opus 5, Sonnet 5.5, Sonnet 5 und Haiku 5.5 auf bezahlten Tarifen 1 Mio. Token; ältere Modelle wie Fable 5, Opus 4.8, Opus 4.7, Opus 4.6 und Sonnet 4.6 sind auf 500.000 begrenzt, alle übrigen auf 200.000. Copilot kann ebenfalls 1 Mio. Token nutzen, aber nur in VS Code und der Copilot CLI und nur mit unterstützten Modellen (darunter Claude und GPT); das große Fenster verbraucht dort mehr Credits.

Wichtiger als die Zahlen ist, was daraus folgt. Ein größeres [Kontextfenster](https://geotoolbox.ai/blog/claude-code-context-window) erlaubt einem Assistenten, eine große Codebasis lange genug im Blick zu behalten, um eine zusammenhängende Änderung über mehrere Dateien vorzunehmen. Dort ist Claude Code am stärksten. Ein kleineres Standardfenster dürfte erklären, warum Copilot-Nutzer berichten, das Werkzeug vergesse den Rest des Repositorys, solange sie das größere Fenster nicht einschalten. Bei lokalen Änderungen in einer Datei, die du ohnehin offen hast, spielt der Unterschied kaum eine Rolle. Wer Dutzende Dateien umbaut, für den ist er entscheidend.

## Preise: Was Copilot und Claude in Deutschland wirklich kosten

Die Listenpreise sind schnell erklärt. Was am Ende auf deiner Rechnung steht, hängt davon ab, wie jedes Werkzeug mit starker Nutzung umgeht, und genau hier hat GitHub 2026 die Regeln geändert.

**Bei den Euro-Beträgen kommt es darauf an, wo du buchst.** GitHub nennt die Copilot-Preise auch auf der deutschen Seite in US-Dollar (Pro 10 $, Pro+ 39 $, Max 100 $ im Monat) und ohne Hinweis auf Steuern. Wie GitHub die Umsatzsteuer beim Abschluss behandelt, konnten wir nicht prüfen, deshalb rechnen wir nichts um. Anthropic nennt auf der deutschen Preisseite ebenfalls nur Dollar-Beträge ohne Steuern. Die Euro-Preise für Claude stammen daher aus zwei anderen Quellen: aus dem Web-Checkout (netto, am 5. November 2026 in einem EU-Konto mit französischer Rechnungsadresse erfasst) und aus dem deutschen App Store (Endpreis). Der Web-Checkout nannte für Pro 18 € im Monat (bei Jahreszahlung 15 € im Monat, also 180 € im Jahr) und für Max ab 90 €, jeweils zuzüglich Umsatzsteuer. Im App Store kostet Pro 22,00 € im Monat (249,99 € im Jahresabo), Max 149,99 € und Ultra 299,99 €. Den Web-Preis für Ultra in Euro haben wir nicht erfasst.

Die alte Faustregel „Copilot ist die berechenbare Variante“ ist nicht mehr haltbar. Seit dem 1. Juni 2026 rechnet [GitHub Copilot in den bezahlten Tarifen](https://github.com/features/copilot/plans) Modell- und Agent-Nutzung in KI-Credits ab, wobei ein Credit einem US-Cent entspricht. Jeder Tarif enthält ein Monatskontingent (15 $ bei Pro, 70 $ bei Pro+, 200 $ bei Max), von dem ein Teil ein variables Flex-Kontingent ist, das GitHub ändern kann. Chat, Agent-Modus, Cloud-Agent, CLI und Drittagenten verbrauchen Credits; Inline-Vorschläge bleiben unbegrenzt, und stärkere Modelle zehren das Kontingent schneller auf. Das Kontingent wird am Monatsersten zurückgesetzt, Reste verfallen. Wer den Agenten im Pro-Tarif intensiv nutzt, hat die 15 $ schnell verbraucht. Das schildern Copilot-Nutzer immer wieder: Das frisch erneuerte Kontingent sei nach einer Woche schon wieder aufgebraucht. Das feste Kontingent an „Premium Requests“ gibt es nur noch für Jahresabonnenten, die bei der anfragebasierten Abrechnung geblieben sind.

Bei Claude läuft das anders, aber nicht zwangsläufig günstiger. [Claude Code ist in Pro, Max und Ultra enthalten](https://geotoolbox.ai/blog/claude-pricing) (20 $, 100 $ und 200 $ im Monat), mit Nutzungslimits in Fünf-Stunden- und Wochenfenstern statt eines Credit-Kontingents. Ist das Limit erreicht, wartest du, bis es zurückgesetzt wird, oder schaltest Nutzungs-Credits ein und zahlst von da an zu API-Preisen weiter. Teams, die eines der beiden Werkzeuge stark auslasten, landen oft bei der API; dort kommt es weniger auf den Tarifpreis an als darauf, wie viele Token eine Aufgabe verbraucht. Wo das Geld dabei versickert, zeigt unser Leitfaden zu [Claude-Code-Tokenkosten](https://geotoolbox.ai/blog/reduce-claude-code-token-costs).

Welches Werkzeug günstiger ist, hängt davon ab, wie stark du es beanspruchst. Bei leichter Nutzung haben beide einen kostenlosen Einstieg, und Copilot Pro mit 10 $ ist der günstigste bezahlte Tarif. Bei starker Agent-Nutzung gehen die Wege auseinander. Beim Claude-Abo bleibt der Preis fest, dafür bremst dich das Limit aus, außer du schaltest Nutzungs-Credits ein. Bei Copilot schrumpft das Credit-Kontingent, und dann stoppst du oder zahlst für den Mehrverbrauch. Nur bei der API steigen die Kosten direkt mit den Token, die eine Aufgabe verbraucht.

## Benchmarks: mit Vorsicht lesen

Manche Vergleichsseiten präsentieren dir eine saubere Benchmark-Tabelle, meist mit SWE-bench Verified, Claude mit Werten im hohen 80-Prozent-Bereich und Copilot dahinter. Sei hier skeptisch, denn viele dieser Zahlen halten einem Blick in die Quelle nicht stand.

Zwei Probleme tauchen immer wieder auf. Erstens sind manche Werte schlicht erfunden: Eine oft kopierte Seite nennt ein genaues Ergebnis für einen Benchmark, den es in keiner Primärquelle gibt. Das zweite Problem fällt weniger auf: Anthropics Systemkarten für die aktuellen Modelle (Fable 5.1, Opus 5.5, Sonnet 5.5 und Haiku 5.5) nennen gar keinen SWE-bench-Verified-Wert. Sie rücken den schwereren SWE-bench Pro in den Vordergrund, bei dem Opus 5.5 laut Karte 89,9 % erreicht und Sonnet 5.5 81,3 %. Ein SWE-bench-Verified-Prozentwert für Opus 5.5 oder Sonnet 5.5 stammt also nicht von Anthropic, und solchen Werten solltest du misstrauen: Meist hat jemand die Zahl eines älteren Modells weitergereicht oder erfunden. Für die Vorgängergeneration gab es einen solchen Wert tatsächlich (Opus 5 mit 96,0 %, Sonnet 5 mit 85,2 %). Deshalb wird eine Zahl, die zu einer älteren Version passt, immer wieder dem neuesten Modell zugeschrieben.

Hinzu kommt ein Denkfehler, der in den meisten dieser Tabellen steckt: Sie messen das Modell und schreiben den Wert dem Werkzeug zu. Copilot und Claude Code können dasselbe Claude-Modell nutzen. Ein Modell-Benchmark sagt damit etwas über den Motor, aber nichts darüber, wie gut das jeweilige Werkzeug daraus fertige Arbeit macht. Wie gut der Agent um das Modell herum gebaut ist, wie er mit Kontext umgeht und wie er sich nach einem fehlgeschlagenen Test fängt, wiegt oft schwerer als ein paar Benchmark-Punkte. Dasselbe gilt, wenn du [Claude mit anderen Coding-Modellen](https://geotoolbox.ai/blog/kimi-k3-vs-claude) vergleichst.

Eine verlässliche Antwort auf „Wer ist beim Programmieren besser?“ fällt enger aus, ist dafür aber nützlicher. Claude Code ist bei selbstständigen Änderungen über viele Dateien durchgehend stark, weil sich sein Kreislauf aus Ändern, Ausführen, Lesen und Korrigieren dort auszahlt. Copilot ist stark bei schnellen Inline-Vorschlägen, bei Arbeit, die im Editor bleibt, und bei der GitHub-Anbindung. Wo beide dasselbe Modell nutzen, unterscheidet sich der Ablauf drumherum. Behandle jede genaue Prozentzahl, die du nicht auf einen Anbieter oder das SWE-bench-Leaderboard zurückführen kannst, als Werbung.

## Wo welches Werkzeug gewinnt

Lässt man das Marketing beiseite, ist die Aufteilung klar.

**Greif zu GitHub Copilot, wenn** die Arbeit im Editor stattfindet und schnell gehen soll: neuer Code mit Inline-Vorschlägen, kleine Änderungen und Boilerplate, ein gängiger Editor mit kaum Einrichtungsaufwand und alles, was direkt GitHub betrifft. Dazu gehören etwa Zusammenfassungen von Pull Requests und Code-Reviews. Ist dein Team auf VS Code oder JetBrains festgelegt und will einen Assistenten, den jeder sofort einschalten kann, ist Copilot die unkomplizierte Standardwahl.

**Greif zu Claude Code, wenn** die Aufgabe über eine Datei hinausgeht: eine Framework-Migration, ein Refactoring, das ein ganzes Modul betrifft, oder ein Feature von Anfang bis Ende. Dazu zählt auch eine Aufräumaktion, die du lieber delegierst und prüfst, als sie selbst zu tippen. Ein Terminal-Agent, der plant, Änderungen über viele Dateien vornimmt und deine Tests ausführt, leistet eine andere Arbeit als eine Autovervollständigung. Für diese Arbeit war Copilots Inline-Modus nie gedacht.

Die übliche Antwort lautet: beides. Viele Entwickler lassen Copilot für die Inline-Vorschläge beim normalen Editieren laufen und wechseln für die aufwendigen, eigenständigen Aufgaben zu Claude Code. Eine gemeinsame `CLAUDE.md` gibt beiden denselben Projektkontext, und in einem bezahlten Copilot-Tarif lassen sich über die Drittagenten-Anbindung sogar Aufgaben an Claude übergeben. Beide zusammen zu betreiben ist also praktikabel und keine Doppelung. Passt nur eines der beiden ins Budget, entscheide danach, womit du die meisten Arbeitsstunden verbringst: Wer meist im Editor tippt, landet bei Copilot, wer meist große Änderungen steuert, bei Claude Code.

## Unternehmen, Sicherheit und DSGVO

Das meiste in diesem Abschnitt ist wichtig, wenn ein Unternehmen entscheiden muss, welches Werkzeug es zum Standard macht. Einiges betrifft aber auch dich als Einzelperson.

**Geistiges Eigentum:** GitHub bietet bei Copilot Business und Enterprise eine IP-Freistellung an (bei Free, Pro, Pro+ und Max ist sie nicht enthalten). Anthropic nennt vergleichbare Schutzzusagen in seinen Commercial Terms. Löst generierter Code einen Urheberrechtsstreit aus, springt der Anbieter also ein, aber nur im Rahmen eines Geschäftskundenvertrags.

**Training mit deinem Code:** Beide Anbieter sagen zu, ihre Modelle nicht mit Geschäftsdaten zu trainieren, solange der Kunde nicht zustimmt, und stellen Organisationen Verwaltungsfunktionen bereit; wie tief Richtlinien, Protokolle und Aufbewahrung reichen, solltest du mit deinen eigenen Compliance-Anforderungen abgleichen. Bei Privatkonten sieht es anders aus. Seit dem 24. April 2026 darf GitHub bei Copilot Free, Pro, Pro+ und Max deine Prompts, Antworten und Code-Schnipsel zum Training seiner KI-Modelle nutzen, solange du nicht widersprichst. Um zu widersprechen, stellst du in den Copilot-Einstellungen „Allow GitHub to use my data for AI model training“ auf „Disabled“. Business und Enterprise sind davon ausgenommen. Ähnlich ist es bei Claude: In den Tarifen Free, Pro, Max und Ultra kann Anthropic deine Chats und Claude-Code-Sitzungen fürs Training nutzen, solange die Einstellung zur Modellverbesserung unter „Datenschutz“ aktiv ist; Anthropic bezeichnet das als Opt-out.

**DSGVO und Auftragsverarbeitung:** Wer personenbezogene Daten in Code, Logs oder Prompts verarbeitet, braucht einen Geschäftszugang mit Auftragsverarbeitungsvertrag (AVV). Bei Anthropic ist der AVV samt Standardvertragsklauseln Teil der Commercial Terms, die für Team, Enterprise und die API gelten. Anthropics eigene API bietet keine EU-Datenresidenz (eine EU-Region lässt sich dort nicht wählen); eine Verarbeitung in der EU bietet Anthropic über AWS Bedrock und Google Cloud Vertex an, bei Microsoft Foundry steht Europa noch auf „Coming soon“ (Stand 5. November 2026). GitHub bietet für Copilot seit dem 13. April 2026 eine EU-Datenresidenz an, allerdings nur für GitHub Enterprise Cloud mit Datenresidenz (EU). Sie muss eigens aktiviert werden (Opt-in) und erhöht den Verbrauch an KI-Credits um 10 %. Für das normale Copilot nennt GitHub keine Verarbeitungsregion.

Der eigentliche Sicherheitsunterschied liegt in der Bauweise. Das Sicherheitsunternehmen Wiz beschreibt ihn so: Claude Code läuft im Terminal und hat damit breiteren Zugriff auf Shell-Befehle, Git und das Dateisystem, Copilot sitzt im Editor (Wiz, März 2026). Ganz so klar ist die Trennung nicht mehr, denn auch Copilots CLI führt lokale Befehle aus. Diese Selbstständigkeit ist bei Claude Code Stärke und größtes Risiko zugleich, denn ein Agent, der Befehle ausführen kann, kann im Prinzip auch einen zerstörerischen ausführen. Anthropic begrenzt das mit Berechtigungsmodi: Standardmäßig prüft ein separates Klassifizierungsmodell an deiner Stelle Aktionen und blockiert, was es für unsicher hält; im manuellen Modus fragt Claude Code vor Änderungen und Befehlen, die du nicht schon freigegeben hast. Außerdem gibt es Allowlists, Sandboxing und dieselben Hooks, die das Werkzeug konfigurierbar machen. Die Verantwortung, den Agenten einzugrenzen, bleibt trotzdem bei dir.

Ob dein Code im Betrieb sicher ist, prüft keines der beiden Werkzeuge, darauf weist auch Wiz hin. Copilots Cloud-Agent lässt auf seine eigenen Pull Requests standardmäßig CodeQL, Secret Scanning und einen Abhängigkeits-Check laufen. Das ist aber eine Prüfung vor dem Merge und kein Schutz zur Laufzeit. Geleakte Secrets und unsichere Muster bleiben deine Verantwortung, egal, wofür du dich entscheidest. Wer eines der beiden Werkzeuge im Team ausrollt, sollte dem Berechtigungs- und Sandbox-Setup mindestens so viel Aufmerksamkeit schenken wie der Funktionsliste.

## Claude oder Copilot? So entscheidest du

Unser Urteil fällt eindeutig aus. **Für die meisten Entwickler ist GitHub Copilot die bessere Standardwahl**, weil die Arbeit meist im Editor stattfindet, der Einstieg 10 $ kostet und du das Modell dahinter wählen kannst, Claude eingeschlossen. **Greif zu Claude Code, wenn die Aufgabe eigenständige Arbeit über viele Dateien verlangt**, bei der sich ein Terminal-Agent lohnt, der plant und sich selbst korrigiert. Keines von beiden ersetzt das andere vollständig, und beide zu nutzen wird immer üblicher.

## Häufige Fragen

### Nutzt Copilot Claude?

Ja. GitHub Copilot arbeitet mit Modellen mehrerer Anbieter: Im Modellwähler kannst du neben GPT und Gemini auch Claude-Modelle wie Sonnet 5 oder, ab Pro+, Opus 5.5 wählen. In bezahlten Copilot-Tarifen lassen sich Aufgaben außerdem über eine Drittagenten-Anbindung (Public Preview) an Claude-Agenten übergeben. Ein Claude-Modell in Copilot ist nicht das eigenständige Claude Code und greift nicht auf ein separates Claude-Abo zurück.

### Ist Claude besser als Copilot?

Bei selbstständiger Arbeit über viele Dateien, etwa bei Refactorings und Migrationen, ist Claude Code meist das stärkere Werkzeug, weil es plant, Änderungen über viele Dateien vornimmt und deine Tests ausführt. Für schnelles Programmieren im Editor und die Arbeit mit GitHub ist Copilot besser. Da Copilot auch Claude-Modelle nutzen kann, kommt es weniger auf das Modell an als auf das Werkzeug um das Modell herum.

### Ist Claude günstiger als Copilot?

Bei leichter Nutzung ist Copilot günstiger im Einstieg: Pro kostet 10 $ im Monat, Claude Pro 20 $. Bei starker Nutzung gehen die Werkzeuge verschieden damit um. Copilot zieht Agent- und Premium-Nutzung von einem monatlichen Kontingent an KI-Credits ab und berechnet dann den Mehrverbrauch oder stoppt. Beim Claude-Abo bleibt der Preis fest, dafür bremst dich das Limit aus, bis es zurückgesetzt wird oder du Nutzungs-Credits zu API-Preisen zuschaltest. Nur bei der API steigen die Kosten direkt mit der Nutzung. Die Euro-Preise je nach Buchungsweg stehen im Preisabschnitt.

### Was sind die Nachteile von Copilot?

Am häufigsten genannt werden drei Punkte: Das KI-Credit-Kontingent kann bei starker Agent-Nutzung schnell leer sein, Copilot kann bei großen Änderungen über viele Dateien den Überblick verlieren, und sein Agent-Modus ist trotz Verbesserungen weniger selbstständig als ein spezialisierter Terminal-Agent. Stark bleibt Copilot bei Inline-Vorschlägen und der Editor-Anbindung.
