Technical SEO decides whether search engines can reach, render and index your pages, the step that content and links build on. In 2026 it serves Googlebot, which renders JavaScript and feeds both classic results and AI Overviews, and also AI crawlers from OpenAI, Anthropic and Perplexity, which often read only the HTML your server sends.

The rules that differ, such as which robots.txt token controls training versus AI search, whether a bot runs JavaScript, and which setting removes you from AI Overviews, are where sites lose visibility by accident.

## What Is Technical SEO?

Technical SEO is the work that lets search engines and AI crawlers reach your pages, render them, index them and serve them.

Google's own floor is short. A page has to be reachable by Googlebot, return HTTP 200 and carry indexable content. Google calls these the [Search technical requirements](https://developers.google.com/search/docs/essentials/technical), and meeting them only makes a page eligible.

AI crawlers add a second set of rules on top of Google's.

## How Google and AI Crawlers Process a Page

Google runs one pipeline. It [processes JavaScript pages in three phases](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics): crawling, rendering and indexing, with rendering queued after the first fetch in a headless Chromium. AI Overviews and AI Mode draw their supporting links from that same Search index, which is why Google says the normal Search requirements apply to them.

### How AI Crawlers Split by Purpose

AI companies split their crawling by purpose, and each purpose has its own user agent:

- **Training crawlers** collect pages for model training: GPTBot, ClaudeBot
- **Search crawlers** build the index behind an AI search product: OAI-SearchBot, Claude-SearchBot, PerplexityBot
- **User-triggered fetchers** load a page because someone asked about it right now: ChatGPT-User, Claude-User, Perplexity-User

### What the Matrix Shows

Three patterns stand out.

First, OpenAI and Anthropic separate training from search, and Perplexity says its crawler is not used for model training.

Second, raw HTML is the shared safe default. Google renders, but ChatGPT-User and Claude-User fetched no scripts in the 2026 log cited below. Agent browsers, such as the Claude-Agent browser Claude uses to complete tasks for users, are the exception: browsers run scripts.

Third, only Google and Bing document page-level controls for AI use.

Google's [AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) adds one requirement: a site "must be included in Search generative AI features in Search Console".

Every site is included by default, and a property inherits the setting from its closest parent property that changed it, so check your domain property too. Google's older [AI features page](https://developers.google.com/search/docs/appearance/ai-features) (December 2025) still says there are "no additional technical requirements".

## Crawlability: robots.txt, Status Codes and Crawl Budget

Crawlability means a bot can request a URL and get a usable answer, and many technical SEO issues start here.

### Why robots.txt Controls Crawling, Not Indexing

robots.txt asks crawlers to stay away from paths; it does not keep a URL out of Google. Google says a page that's [disallowed in robots.txt can still be indexed](https://developers.google.com/search/docs/crawling-indexing/robots/intro) if other sites link to it. The standard itself, [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html), says: "These rules are not a form of access authorization."

Password-protect a staging site or private page: robots.txt and noindex are not security. For a public page that should only stay out of Search, Google recommends noindex. Don't also disallow that URL in robots.txt, because Google has to crawl the page to see the tag.

Our [SaaS SEO guide](https://geotoolbox.ai/blog/saas-seo) covers the app, staging and old docs versions a software domain should keep out of the index.

Googlebot ignores crawl-delay, which its [robots.txt spec](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec) lists as unsupported, while [Anthropic says](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler) its bots respect it "where appropriate".

Each crawler follows the group that names its user agent and falls back to `*` otherwise, so you only name the bots you want to treat differently. Adding these groups asks OpenAI, Anthropic and Google not to train on your pages (Google-Extended is a control token, not a crawler) and leaves every search crawler on its current rules.

Review any existing groups for these bots too: robots.txt combines them, and a more specific Allow line still beats `Disallow: /`. The Google-Extended group also removes your pages from grounding in Gemini Apps, so leave it out if you want Gemini answers to use them.

```
User-agent: GPTBot
Disallow: /

User-agent: ClaudeBot
Disallow: /

User-agent: Google-Extended
Disallow: /
```

The file's own status code matters too. Under [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html), a 4xx means a crawler may fetch anything, while an unreachable file (a server error) means it must assume everything is disallowed.

### Your CDN Can Overrule robots.txt

CDN and firewall bot rules run before robots.txt is read, so a file that allows OAI-SearchBot does nothing if the edge returns a 403. Cloudflare, for one, [began asking every new domain](https://www.cloudflare.com/press/press-releases/2025/cloudflare-just-changed-how-ai-crawlers-scrape-the-internet-at-large/) whether to allow AI crawlers on July 1, 2025, with blocking as the default.

Perplexity's [crawler documentation](https://docs.perplexity.ai/docs/resources/perplexity-crawlers) tells site owners they may need to allow its bots explicitly in a web application firewall.

### Crawl Budget Is a Large-Site Problem

Google's [crawl budget guide](https://developers.google.com/crawling/docs/crawl-budget) is written for sites with more than 1 million unique pages that change weekly, more than 10,000 that change daily, or a large share of URLs stuck in "Discovered - currently not indexed", and Google calls those numbers rough estimates. Below that, an unindexed page usually has another cause, such as duplicate content or thin content. If you publish thousands of pages from one template, our [programmatic SEO guide](https://geotoolbox.ai/blog/programmatic-seo) covers getting them crawled and indexed.

What wastes crawling at any size: redirect chains, soft 404s ("soft 404 pages will continue to be crawled, and waste your budget"), and slow or failing servers. Google lowers its crawl rate when responses slow down or return 5xx or 429 codes.

## Rendering: What Each Crawler Actually Sees

If your main text only appears after JavaScript runs, Google will usually see it and the AI fetchers from OpenAI, Anthropic and Perplexity mostly will not.

Google renders in that queued second step, which can lag the crawl. [Bing's guidelines](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a) ask you not to hide critical content behind client-side rendering, because "content that cannot be reliably rendered may not be indexed or selected for grounding results."

In December 2024, [Vercel and MERJ's log analysis](https://vercel.com/blog/the-rise-of-the-ai-crawler) of Vercel's network found that "none of the major AI crawlers currently render JavaScript". On nextjs.org, ChatGPT's crawler spent 11.50% of its requests on JavaScript files and Claude's 23.84%, without executing them.

That has changed for OpenAI's search crawler. On October 22, 2026, [Genezio](https://genezio.com/research/openai-crawler-runs-javascript/), which sells AI-visibility software, published a test on its own site in which a crawler from OpenAI's IP ranges called back an endpoint that only running JavaScript could reach.

[Forge's 30-day log of one news site](https://www.forgeaibotlog.com/articles/can-ai-crawlers-execute-javascript/), to September 24, 2026, caught OAI-SearchBot loading a single page the way a browser does, once in 1,738 requests carrying that bot name (Forge did not check them against OpenAI's IP list), and Forge says a log cannot show whether the scripts ran.

OpenAI has not documented any of it. In the same log, ChatGPT-User, Claude-User and PerplexityBot fetched no scripts.

Two other tests muddy the picture. A [JS SEO Lab beacon test](https://jsseo.dev/findings/javascript-execution-has-two-depths/) logged GPTBot running inline scripts, and a [searchVIU test](https://www.searchviu.com/en/guides/schema-markup-ai/) run on October 30, 2025 suggests script-written content can reach Perplexity's index.

## Indexing, Canonicals and Sitemaps

Indexing is Google's decision, and you influence it with consistent signals: one canonical URL per piece of content, no accidental noindex, and a sitemap that lists only pages you want indexed.

Google Search Console for technical SEO work starts with the Page indexing report, which groups the URLs Google left out by the reason it gives.

Use a noindex meta robots tag to keep a page out of results, and canonical tags or redirects to consolidate duplicates.

Google treats a canonical tag as a strong signal, not an order, so it works best when internal links, sitemaps and redirects point the same way. Our guide to [canonical tags](https://geotoolbox.ai/blog/canonical-tags) covers how Google and AI engines pick one URL.

### Sitemaps and IndexNow

Google says a site of [about 500 pages or fewer](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview) that is fully linked internally may not need a sitemap. Bing adds IndexNow, a ping that tells Bing when a URL is added, updated or removed, and [its guidelines](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a) tie that freshness to Copilot answers. See our [XML sitemap guide](https://geotoolbox.ai/blog/xml-sitemap) for setup.

### "Crawled - Currently Not Indexed"

In Google Search Console, this status means Google fetched the page and chose not to index it, for now. It is not an error code, and Google does not index every URL it crawls.

Work through it in this order:

1. Check whether the page duplicates another URL, and whether Google picked a different canonical
2. Check how many internal links point to it, and from where
3. Check whether it adds anything the indexed pages on the same topic do not

The Request Indexing button only asks Google to [crawl the URL again](https://support.google.com/webmasters/answer/9012289?hl=en), so it rarely changes the outcome while the cause is still there.

### Faceted Navigation

Faceted navigation creates duplicate URLs at scale. Filters and sort orders can create thousands of near-identical URLs. To keep crawlers off the combinations nobody searches for, Google's [faceted navigation guidance](https://developers.google.com/crawling/docs/faceted-navigation) prefers blocking them in robots.txt or putting filters in URL fragments; it calls canonical tags generally less effective for that. If those URLs are already indexed, noindex them first and block them only once they drop out. Our [ecommerce SEO guide](https://geotoolbox.ai/blog/ecommerce-seo) walks through that decision per filter.

B2B catalogs add another crawl problem: specs and certificates published only as PDFs or behind forms, which our [B2B SEO guide](https://geotoolbox.ai/blog/b2b-seo) covers.

## Site Architecture and Internal Links

Search engines and AI crawlers find most pages by following links, so your internal links decide what gets discovered first and what looks important.

Use plain `<a href>` links. [Bing's guidelines](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a) ask for exactly that, with relevant anchor text, and links that only exist after a click handler runs are invisible to fetchers that skip JavaScript.

Keep important pages close to the homepage through category pages and breadcrumbs. What matters is that every page you want indexed has a crawlable path to it. Keep the URL structure short, readable and stable, because every change needs redirects.

### Orphan Pages and Broken Links

Orphan pages, with no internal links pointing at them, are the usual casualty of redesigns and CMS migrations.

Broken internal links waste crawling for every bot, AI fetchers included. A full site audit, as in our [SEO audit checklist](https://geotoolbox.ai/blog/seo-audit), finds orphan pages and broken links at scale.

### Retiring URLs: Redirect or 404

When you retire a URL, redirect it to a page that genuinely replaces it. If nothing does, return 404 or 410, which [Google recommends](https://developers.google.com/crawling/docs/crawl-budget) for permanently removed pages, and update the links that pointed to it.

## Page Experience: Core Web Vitals, Mobile and HTTPS

Core Web Vitals are the technical SEO factors measured on real visitors: loading, responsiveness and layout stability. Google says good scores align with what its [core ranking systems seek to reward](https://developers.google.com/search/docs/appearance/core-web-vitals), but they are one signal among many, and relevance comes first.

### Mobile-First Indexing and HTTPS

Google indexes the mobile version of your pages, [crawled with the smartphone agent](https://developers.google.com/search/docs/crawling-indexing/mobile/mobile-sites-mobile-first-indexing), so content or links missing on mobile are missing for Google. And pages should be served over HTTPS on one host, with HTTP URLs and the other host version (www or non-www) redirecting to it.

### Does Speed Help AI Citations?

We have not seen published evidence that it does, and none of the OpenAI, Anthropic or Perplexity crawler pages we captured mention page speed.

## Structured Data and hreflang

Structured data labels what a page is about in a format machines parse without guessing. Write it as JSON-LD and keep it identical to what the page shows.

Google's [AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) says: "Structured data isn't required for generative AI search, and there's no special schema.org markup you need to add." It still recommends markup for rich result eligibility. [Bing's guidelines](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a) say structured data "may support clearer grounding but does not guarantee visibility or grounding traffic."

Whether markup raises AI citations is a separate question. In the one intervention study we know of, [Ahrefs tracked 1,885 pages](https://ahrefs.com/blog/schema-ai-citations/) that added schema and found AI citations barely moved. Our [schema markup for AI search](https://geotoolbox.ai/blog/schema-markup-for-ai) breakdown covers the studies.

### Validating Structured Data

Validate before you ship. A JSON-LD block with a syntax error can't be read at all, and Bing warns that misleading markup "may be ignored."

### Using hreflang on Multilingual Sites

hreflang tells Google which language or regional version of a page to show. Each value is a language code in [ISO 639-1 format](https://developers.google.com/search/docs/specialty/international/localized-versions), optionally followed by a region code (en-US, fr-CA).

The common failures are one-way annotations (the French page names the English one, not the reverse) and annotations pointing at redirected or noindexed URLs. Link every language version to itself and every other, point only at canonical URLs, and add an x-default value for the fallback page.

None of the AI vendors' crawler pages we captured mention hreflang. What they can use is a separate, crawlable URL per language that works in plain HTML.

## A Short Technical SEO Checklist

These technical SEO best practices build on each other. A page that cannot be fetched gains nothing from schema, so the first items matter most:

1. **Access:** important URLs return 200, robots.txt allows the bots you want, and your CDN does not block them
2. **Rendering:** main text and links are in the raw HTML (the view-source test)
3. **Indexing:** no stray noindex, one canonical per page, a sitemap of canonical URLs only
4. **Architecture:** every important page has a crawlable internal link path; retired URLs redirect to a real replacement or return 404 or 410
5. **Page experience:** Core Web Vitals pass on field data, on mobile, over HTTPS
6. **Structured data:** valid JSON-LD that matches the visible page; hreflang links every language version to itself and every other
7. **AI controls:** each robots.txt group, snippet setting and Search Console setting chosen on purpose
8. **Measurement:** the Generative AI performance report in Google Search Console, Bing's AI Performance report, and server logs filtered by user agent

Start with item 1. Paste your domain into the free geotoolbox AI Crawler Checker to see which AI bots your robots.txt blocks on the homepage path, then run the Agent Readiness scan to see what your firewall returns to them.

### Measuring AI Crawlers and Citations

Anyone can fake a user agent string, so in logs check claimed AI bots against the IP lists OpenAI, Anthropic and Perplexity publish for their crawlers. On Google's side, the [AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) points to a Generative AI performance report in Google Search Console.

## Frequently Asked Questions

### Do you need to know how to code to do technical SEO?

No, but you need to read code. Most of the work is diagnosis: reading robots.txt, status codes, page source and Search Console reports. Fixes like server-side rendering or redirect rules usually go to a developer.

### Does technical SEO still matter with AI search?

Yes, and arguably more. Copilot runs on Bing's index, and AI fetchers that read raw HTML are less forgiving than Googlebot. A page they cannot fetch or read cannot be cited.

### What is the 80/20 rule in technical SEO?

Most of the impact comes from a few checks: whether important pages can be crawled, rendered and indexed. Fix access, raw-HTML content and indexing signals before spending time on scores like Lighthouse performance or minor validator warnings.

### Can ChatGPT do technical SEO?

It can explain an error, draft robots.txt rules, redirects or JSON-LD, and summarize a crawl export you paste in. It cannot see your server logs, your Search Console data or what each bot actually received, so check its suggestions against those before you ship a change.
